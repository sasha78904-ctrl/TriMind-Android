# TriMind ECU × HEXplorer — експериментальний X/Y/Z читач v2

## Фактично виконано

- Оригінальний GPLv3+ A2L-парсер `adhoc2/HEXplorer` (commit `c67a73f2fd1b43a999012c95a04181c6d52e51aa`) раніше скомпільовано та запущено. Його JSON з `3999` CHARACTERISTIC використано як джерело назв, адрес, типів, RECORD_LAYOUT і COMPU_METHOD.
- Власний **C++ читач BIN**, адаптований за логікою `HexFile::getDecValues`, скомпільовано тут як `hexplorer_xyz`; він читає реальний `mers nov` лише в режимі READ-ONLY.
- `RECORD_LAYOUT`/ліміти осей/явні `NUMBER` отримано з цього ж A2L окремим парсером TriMind v0.5. Відповідність об'єктів до незалежного оригінального JSON HEXplorer перевірена за назвами та адресами.
- 12 синтетичних позитивних/негативних тестів C++ виконано та пройдено.
- Повна інтеграція оригінальних `HexFile` **та** `Data::readHexValues` у єдиний Linux-бінарник **ще НЕ виконана**. Не слід називати цей адаптер «оригінальний повний HEXplorer».

## Реальний результат `mers nov`

| Тип | В A2L | Сирі дані прочитані | Відхилені |
|---|---:|---:|---:|
| MAP | 145 | 2 | 143 |
| CURVE | 173 | 3 | 170 |
| VALUE | 3 112 | 3 112 | 0 |
| VAL_BLK | 569 | 569 | 0 |
| **Усього** | **3 999** | **3 686** | **313** |

**Чому багато VALUE та VAL_BLK читаються?** Одне/кілька чисел за адресою значно легше прочитати, ніж перевірити реальні осі двовимірної карти. Це не доказ, що адреси правильні саме для цього SW.

Дві MAP побайтово збігаються з поточним TriMind v0.5 (повні масиви X/Y/Z): `FlMng_rLmbdFullLd_MAP` (4×4, всі Z=4), `InjCrv_phiMI1Max_MAP` (8×8, всі Z=0). **Немає жодної VERIFIED MAP**, оскільки використаний A2L не підтверджений для Bosch SW `1037376898` і адресна база `0x800000` залишається гіпотезою.

Раніше простіший адаптер приймав `PCR_pDvtMin_MAP`; новий C++ читач відхилив її через **немонотонні X/Y**, тому це **не підтверджена третя карта**.

## Вміст ZIP

- `hexplorer_xyz` — локально скомпільований Linux x86_64 адаптований читач.
- `hexplorer_xyz.cpp` — його вихідний код (GPL-3.0-or-later).
- `test_native_xyz.py` — 12 регресійних тестів.
- `native_a2l_manifest.tsv` — реєстр із оригінального HEXplorer A2L JSON з полями, доповненими розкладками TriMind.
- `hexplorer_adapted_xyz.jsonl` — 3 999 результатів сирого читання.
- `RESULTS.json`, `map_comparison.json`, `TriMind_v05_result.json` — зведення та порівняння.
- `run_compare.py` — скрипт відтворення за наявності початкових файлів і модулів TriMind у Python.

## Прямий запуск без Qt

```bash
./hexplorer_xyz native_a2l_manifest.tsv mers_nov.bin 0x800000 BE output.jsonl
python3 test_native_xyz.py
```

Адресна база навмисно вказана як параметр, а не захардкожена у підтверджені метадані. Файли описів та вихідний `mers_nov.bin` зберігаються окремо.

## Для подальшої розробки

Подальша інтеграція нативного `HexFile` і `Data::readHexValues` вимагатиме виділення їх від GUI / WorkProject, а потім регресійного побайтового тесту; окремий адаптер уже дозволяє тестувати BIN без очікування повної Qt-збірки.

## Додаткова незалежна перевірка CURVE

Після початкового v2 незалежний Python-декодер прочитав 173 CURVE з того самого BIN (явні `NO_AXIS_PTS_X`, `AXIS_PTS_X`, `FNC_VALUES`; без підстановки максимального числа точок). Результати:

- **3 `MATCH_RAW`**: `PCR_facCtlIAT_CUR`, `Rail_PCVCtlIKiNeg_CUR`, `Rail_pSetPointBattMin_CUR`.
- **170 `BOTH_REJECTED`**: і Python, і C++ відхилили структуру.
- **0 розбіжностей X/Z**, **0 випадків, прийнятих лише одним із двох читачів**.

Файл `curve_comparison.json` містить всі 173 порівняння.

## Перевірка GitHub Actions

На експериментальній гілці окремий CI job `hexplorer-xyz-experiment.yml` успішно скомпілював C++ адаптер та підтвердив **12/12** синтетичних тестів. Журнал: `research/ecu_hexplorer_shadow/build_status/latest_xyz_ci.txt`.

## Технічна межа

Це **дві робочі частини в одному комплекті**: скомпільований автентичний HEXplorer A2L CLI та експериментальний C++ читач X/Y/Z, який не лінкує оригінальний `Data::readHexValues`. Повна нативна інтеграція `HexFile`/`Data` — окреме невиконане завдання. Жодна карта не має незалежно підтвердженої відповідності ECU.
